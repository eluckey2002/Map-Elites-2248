# Conditional phase orchestration — prepared, not run

The running control harness and RECOVERY_PLAN.md remain immutable. This code
uses the registration's explicit allowance: "Additional phase orchestration may
only call these unchanged measurement paths, and its identity must be pinned
in its raw artifact." No new decision bar, seed allocation, budget, proposal
sequence or confirmation allowance is introduced.

`run-proposals.js` refuses to start until all twelve controls are complete,
their original aggregate bars pass, and the independent control arithmetic
and completed-job journal qualify. It also refuses existing output markers.
Before the first proposal it records the reachable phase commit and hashes of
its orchestration, planning reader, search-space code, executable control audit
and immutable inputs. The audit's committed hash is verified before execution.
Each panel rechecks those identities and the frozen recovery registration.

For each of the original fifteen generation proposals, a separate planning
process reads three distinct historical owner-faster diagnostic boards and
creates exactly one literal configuration as code, with a hypothesis. The
worker never imports this planning process. G's original reference is shared,
not replayed. Fresh rechecks consume R1–R11 once each; their results, rather
than gate scores, determine the logged outcome. Full-panel funding is checked
before a paired recheck dispatch. Dispatches, completed jobs, panels, counters
and CSV rows persist before the next decision. A loss stops rather than resumes.

The carried G champion ran inert qualification callbacks during its games.
Its physical CPU total includes that instrumentation. Gate CPU ratios cannot
estimate pure policy overhead; the raw artifact and stdout state this caveat.
Fresh R, S and F references run without those callbacks. No reference is replayed
and no estimated instrumentation cost is subtracted.

Joint search is conditional on ACCEPTED changes. Each accepted coordinate's
domain contains accepted doses and their immediate declared neighbors. Rank
complete Cartesian configurations by the sum of index distances from the best
fresh accepted dose on each coordinate; dose order breaks ties. Retain at most
the registered 31 complete configurations, with all active coordinates present
together. This rank is determined before S games. The shared reference, all
selected candidates and one fresh best-candidate recheck fit the joint budget.
Untested configurations remain untested. A lack of a fresh recheck block closes
Path D. With no ACCEPTED proposals, print the required skip and NO_CANDIDATE
statements and release the joint allocation to the buffer. Select a candidate
by fresh recheck mean moves saved, breaking ties by fewer changes.

`run-confirmation.js` is prepared but cannot run without the assigned committed
protocol, the exact frozen candidate, complete qualified proposals and their
independent audit. Freeze all mandatory measurement inputs, thresholds and F
before use. The candidate is literal `module.exports = <JSON>` code, parsed
without execution and validated against the audit's format before any output
marker or dispatch. It refuses a previous confirmation directory or raw artifact and
checks funding for both arms before dispatch. Ten-seed journal jobs preserve
the original 58 × 150 denominator. Full raw pairs are written through
persist-before-verdict before computing the verdict. SUPPORTED requires the
original nonnegative net-win and strictly positive lower 95% speed endpoint;
net win regression or a strictly negative upper speed endpoint is FALSIFIED;
other cases are INCONCLUSIVE. The overall result governs; secondary and
per-level reports cannot override it. CPU and wall time are separate physical
measurements, with no claim of matched compute.

`proposal-recompute.js` imports Node builtins only. It independently checks
paired arithmetic, decision outcomes, identities, accounting, cell coverage,
disjointness, journals, dose-response, joint space and candidate selection.
Its `--confirmation` mode additionally checks the one-shot raw pairs,
all/late/other/per-level numbers and physical compute. `--json` returns the
same deterministic confirmation audit for an executable closeout receipt.
This is a same-author re-implementation, not independent scientific verification.

The focused qualification plays no games: synthetic outcomes, seed arrays,
temporary historical-board fixtures, source-code configurations, CSV quoting,
budget refusal and an unregistered-confirmation refusal. Actual proposals,
joint search, candidate freeze, protocol registration and confirmation remain
UNVERIFIED_NOT_RUN until their respective persisted artifacts exist. Adoption,
scientific acceptance and merge remain outside this authorization.
