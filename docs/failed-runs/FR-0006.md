# FR-0006 — LC-0002 qualification preflight used the wrong contract hash

**Occurred:** 2026-09-28

**Run:** `LC-0002-qualification-attempt-1`

**Stage:** preflight, before the decision panel was collected or its raw
artifact was created

## Observed failure

The qualification command supplied expected contract SHA-256
`43d281d8736d2225a0dddb826ca26d2fb0959ac4327a9135d18273838a9b45cf`.
The committed contract actually hashed to
`23fba043366d5b0d4ec1261ca45e85dc31ac0ae6b156c8c11eaa812a30ddc57d`.
The harness rejected the mismatch and exited before resolving the recording or
collecting a panel cell.

## Root cause

The command accepted four manually transcribed expected hashes. The contract
hash was not derived by the command from a mechanically created, committed
identity manifest, so an unrelated value could be pasted into the invocation.

## Prevention

`tools/qualify-built-reservoir-proxy.js` now has a registration mode that
derives one immutable manifest directly from the named recording, contract,
champion, engine, probe, and harness. Qualification accepts that manifest
instead of individual expected-hash arguments and rechecks every bound file.

`solver/tests/builtReservoirProbe.test.js` proves the manifest binds every
input used by collection, while the existing coherent-substitution test proves
that changing the recording without updating the trusted manifest is rejected.
The retained panel remains unspent because attempt 1 stopped before collection.
