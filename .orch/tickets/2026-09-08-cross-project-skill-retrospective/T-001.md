## Frozen acceptance criteria

1. Each recommended candidate names a recognizable trigger, inputs, procedure, output, and verification boundary.
2. Each candidate has direct evidence of actual use, not merely an idea in chat or backlog.
3. Cross-project value is explicit: the method transfers without depending on 2248 rules or data.
4. Recommendations distinguish a new skill from a script, reference note, or specialization of an installed skill.
5. Findings are ranked by expected reuse and leverage, and include important non-candidates.
6. Claims cite the repository source that supports them and state evidence gaps or contradictions.

## Named oracle

The frozen rubric above is the adjudication oracle. A candidate is **strong** only if all five properties are supported: recurrence, portability, bounded contract, independently checkable output, and a meaningful gap beyond an existing generic orchflows skill. A candidate supported by one workflow or lacking an independent oracle is **incubate**, not ready. Project-specific mechanics are **do not extract**.

## Evidence rungs

- **Rung 1:** one primary artifact demonstrates the complete method.
- **Rung 2:** two independent repository surfaces demonstrate recurrence or reusable enforcement (for example executable plus test/protocol/ledger receipt).
- **Rung 3:** demonstrated in another project; outside this ticket's bound unless already present in recorded history.
