# T-001 - Decide the safest repository trust-baseline course

## Question

What is the safest next course for regaining a trustworthy repository baseline without discarding useful work or promoting uncertain evidence?

## Source policy and bound

- Use only the current checkout, the local Git object database, cached `origin/*` refs, and primary repository artifacts reachable from those refs.
- Do not fetch, switch branches, edit evidence records, clean files, delete refs, or publish changes.
- Inspect all 10 cached remote refs, the sole local branch and worktree, up to 50 recent commits, the baseline/universe verification packets on `origin/main`, and the three commits unique to the one unmerged remote branch.
- Treat chat and summary documents as navigation only. Preserve ledger proof classes and report contradictions explicitly.

## Acceptance criteria

- [x] Classify every cached branch tip as merged into `origin/main`, identical to it, or carrying unique commits.
- [x] Identify whether the current checkout is a trustworthy active baseline or a stale view.
- [x] Identify the repository mechanisms that protect evidence and state what their recorded verification actually establishes.
- [x] Give one conservative next course, ordered so no branch or evidence is deleted before preservation and verification.
- [x] State contradictions, dead ends, and what the bounded investigation did not cover.

## Named oracles

- Branch ancestry: pre-existing Git DAG, checked with `git branch -r --merged/--no-merged origin/main` and `git rev-list --left-right --count origin/main...<ref>`.
- Checkout state: pre-existing Git index/worktree, checked with `git status --short --branch` and `git worktree list --porcelain`.
- Baseline and evidence controls: the checked-in verification commands and receipts named by the baseline/universe run packets on `origin/main`; no claim is accepted beyond those receipts without rerunning its named oracle.

## Result

### Status and result identity

- **status:** complete
- **evidence packet:** this ticket
- **bound applied:** nine live remote branch heads, one symbolic default, one local branch/worktree, 40 recent commits, the two named verification packets, and the three commits unique to the sole unmerged branch

### Verification

- **Branch ancestry oracle: PASS.** Live `git ls-remote --heads origin` matched all cached branch identities. Eight remote branch tips are ancestors of `origin/main`; `origin/codex/universe-map-v1` is identical to `origin/main`; `origin/worktree-deterministic-2048-solver` alone is unmerged, with three unique commits and 15 added files.
- **Current-checkout oracle: FAIL as a canonical baseline.** The clean checkout is `level-curve-retune` at `788cfac`, 28 commits behind `origin/main` at `9016690`. It does not contain required baseline ancestor `8508c3b`. The live GitHub default branch also resolves to `level-curve-retune`.
- **Main control-plane oracle: PASS on preserved repository bytes, FAIL on this machine's ordinary converted working-tree bytes.** With `core.autocrlf=false`, Universe verification passed, the build drift check passed, and the Universe plus baseline-control tests passed 25/25. With the machine's configured `core.autocrlf=true` and no repository `.gitattributes`, the same snapshot failed the protected-artifact SHA-256 check and an LF-only `CURRENT.md` assertion. A byte-preserving `git show` confirmed the committed artifact SHA-256 is the expected `ab8ed417...`; conversion produced `6b497a34...`.
- **Broad regression oracle: expected red.** On the preserved-byte `origin/main` snapshot, the solver suite was 233/236. The only failures were the three deliberately stale receipt identities already named by the baseline and Universe packets: `candidate-levels-52.json`, `candidate-levels-54.json`, and `candidate-levels.json`.
- **Curve oracle: PASS.** `node solver/verify-loop.js` passed all seven checks across 53 levels; the sampled hardest-level win rate was 92%, lockout 0%, and result `PASS`.

### Findings

1. **The immediate navigation baseline is wrong, confidence high.** GitHub and this checkout default to the obsolete feature branch even though `origin/main` contains the admitted stabilization and Universe-map work. Sources: live Git refs; `.orch/runs/2026-08-28-git-baseline-stabilization-v2/worklog.md` on `origin/main`; `tools/verify-repo-baseline.js` on `origin/main`.
2. **The branch pile is mostly retained ancestry, not competing work, confidence high.** Every remote branch except the deterministic solver line is contained in `main`; the three `safety/*` refs are protected identities named by the baseline guard. The deterministic solver line is explicitly recorded as parked and remains structurally separate. Sources: Git DAG; baseline worklog, iteration 7; unique-commit diff for `origin/worktree-deterministic-2048-solver`.
3. **Known bad evidence is being surfaced rather than silently greened, confidence high.** The full suite deliberately remains red for three stale receipts. The Universe Map separately says the latest 23-cell MAP-Elites artifact is verified but not ledger-admitted, and that `CURRENT.md` is stale. Sources: `solver/tests/receiptGate.test.js`; `UNIVERSE.md`; `.orch/runs/2026-08-28-universe-map-v1/worklog.md` on `origin/main`.
4. **The verification layer has a newly confirmed Windows portability defect, confidence high.** Exact-byte evidence and generated-view checks depend on LF bytes but the repository has no `.gitattributes`; normal Windows conversion breaks the verifier even though committed blobs are correct. This is an operational verifier defect, not proof that the protected artifact is corrupt.
5. **No bounded audit can establish that unknown defects do not exist, confidence high.** The controls establish identity, freshness, corpus closure, replay consistency, selected ledger standing, and the sampled curve. They do not independently validate every historical semantic claim, solver proof, experimental design choice, or omitted corpus item.

### Contradictions

- The baseline worklog records canonical `main`, while the live GitHub default and this Windows checkout still select `level-curve-retune`. The worklog's canonical claim is valid for the environment it promoted; it did not make this checkout or GitHub's default selector current.
- The Universe worklog reports its verifier green, while a normal Windows materialization fails. Both observations are reproducible: the committed LF bytes pass; automatic CRLF conversion breaks exact hashes and an LF-only assertion.
- A clean `git status` here coexists with a non-canonical checkout. Cleanliness proves only absence of local changes, not freshness or authority.

### Recommended course

1. Freeze new experiments briefly. Repair the verifier's Windows byte/line-ending behavior on a task branch from `main`, and require the same protected identities to pass in a normal Windows checkout and the existing Unix-style environment.
2. After that repair passes, change GitHub's default branch to `main`, create/reset the local tracking branch to the exact remote tip through a non-destructive branch switch, and run the live baseline guard plus Universe, full-suite, and curve gates.
3. Preserve the three `safety/*` branches and the deterministic-solver branch. Do not merge the solver branch merely to reduce branch count. Classify it as parked until its game/product direction is explicitly reopened.
4. Only then consider pruning the already-merged `codex/*` and old feature branches. Before deletion, audit unreachable objects/reflogs and retain a dated branch-disposition receipt.
5. Start the next research milestone from the ledger-admitted frontier, not from the newest artifact: the 23-cell artifact remains verified-but-not-admitted, and the three stale candidate receipts stay red until explicitly resolved rather than exempted.

### Dead ends

- The first parallel Git probe could not launch under the Windows sandbox; smaller isolated probes succeeded.
- A default `git archive` snapshot was not byte-preserving under `core.autocrlf=true`; it was useful as the negative control, not as evidence of committed corruption.
- The first curve-gate process outlived its polling wrapper and its result was not recoverable; the tracked rerun completed and passed.

### Gaps left by the bound

- No fetch changed local remote-tracking refs; live heads were checked with `ls-remote` only.
- Unreachable Git objects, reflogs, GitHub branch-protection rules, PR history, and recovery material outside this checkout were not audited.
- The deterministic solver branch's claims were not rerun or admitted; only its ancestry, scope, and recorded parked status were inspected.
- Historical ledger claims outside the current Universe selection and named gates were not semantically re-proven.
