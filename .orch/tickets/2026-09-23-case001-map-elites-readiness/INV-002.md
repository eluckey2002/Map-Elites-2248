## 6. Protocol-before-run behavior

### Intended controls

The current guard is designed to:

- refuse a reportable run without `--protocol RESULT-NNNN`;
- require the protocol to exist in Git history before compute;
- reject placeholder, empty, rewritten, reopened, or already-reported protocols;
- freeze source identities from the registration commit;
- stamp `protocolCommit` into produced artifacts;
- allow explicitly stamped exploratory output while preventing it from supporting a generalizing ledger claim.

### Executed verification

- `node --test solver/tests/experiments.test.js`: 31 tests, 24 passed, 7 failed.
- `node tools/verify-experiments.js`: `EXPERIMENT GATE FAILED`; 17 existing protocols were falsely reported empty or unreadable at their registration commits.
- Direct Git control:
  - `git show b09737b5:experiments/RESULT-0020/protocol.md` succeeds.
  - The same object read with `experiments\RESULT-0020\protocol.md` fails.
- Root cause surface: `solver/experiment-guard.js` and `tools/verify-experiments.js` construct repository-relative paths with `path.join`; `showAtCommit` passes those paths unchanged into the Git object expression `${sha}:${relPath}`. On Windows, the resulting backslashes are not valid tree separators.

This is a concrete execution-host incompatibility. The protocol contract is conceptually specified, but its enforcement cannot currently be confirmed on the host where U1 and later experiments would run.
