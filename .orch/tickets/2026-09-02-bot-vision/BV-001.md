# Bot Vision: inspect every decision in a short bot game

## Objective

Give the owner a locally runnable visual analytics surface where one exact bot
game can be replayed move by move and every recorded decision can be inspected:
the board transition, selected chain, candidate pool, raw component values,
policy weights, weighted contributions, predicted next chain, and selection
reason. Changing displayed weights may rerank the recorded candidate pool as a
hypothetical; it must never rewrite the recorded move or claim a new rollout.

## Fixed inputs

- Repository baseline: `c025b1a617c99e72df31ca4b57d5b69824ea0a3d`.
- Product boundary and unresolved questions: `.orch/tickets/2026-09-02-bot-game-visibility-audit/BGV-001.md`.
- Existing deterministic session seam: `solver/record-session.js`.
- Owner requirements from the active session: full short-game visibility,
  Top X moves, weights, current and next-chain value, and live reranking.

## Acceptance criteria

1. **Recorded choice behavior is preserved.** `analyzeMove` and `chooseMove`
   select the identical chain on Levels 1, 20, 30, 40, 52, and 53 for seeds 0
   and 1. The known Level 52 seed 2000000 session still wins in 12 moves with
   score 109440. Oracle: automated Node tests invoking the real bot and session
   seams. Oracle class: `test`. Provenance: `pre-existing`.
2. **Every decision is reconstructable.** Each move record contains the exact
   board before and after, spawn delta, considered candidate chains, actual
   selected chain and reason, policy parameters, raw components, weighted
   contributions, predicted next chain, survivor outcome, and session/code
   identities. Component totals are independently recomputed in the test.
   Target and bomb overrides are explicit rather than folded into a normal
   weighted score. Oracle: automated schema and arithmetic assertions over a
   real deterministic recording. Oracle class: `test`. Provenance:
   `pre-existing`.
3. **The local session API is exact and bounded.** A server created on an
   ephemeral port returns the identified Level 52 seed 2000000 session from
   `/api/session`; malformed or unavailable level/seed inputs return 400.
   Oracle: automated HTTP test against the exported server factory. Oracle
   class: `test`. Provenance: `pre-existing`.
4. **The primary workflow works in a real browser.** The owner can run a level
   and seed, move through all 12 decisions, play/pause, change Top X and sort,
   click a candidate to preview it, and change weights to see a hypothetical
   rerank while the actual recorded winner remains visibly fixed. The page has
   no browser-console errors. Oracle: in-app browser interaction against the
   running local server. Oracle class: `behavioral`. Provenance: `pre-existing`.
5. **The surface is legible at desktop and mobile widths.** The implementation
   retains the concept's information hierarchy: board first, candidates second,
   decision explanation and weights visible without ambiguity. Oracle: visual
   comparison of the generated concept and implementation screenshots at
   1440x900 and 390x844, recorded as a five-point fidelity ledger. Oracle class:
   `human-review`. Provenance: `pre-existing`.
6. **Claims stay narrow.** The UI uses language such as `Bot candidate pool`,
   `recorded choice`, and `hypothetical rerank`; it does not say `best move`
   without qualification or imply global optimality. Experiment, ledger, rule,
   score, and default-policy files remain unchanged. `git diff --check` passes.
   Oracle: changed-path and rendered-copy inspection plus Git whitespace check.
   Oracle class: `inspection`. Provenance: `pre-existing`.

## Risks

- This is an inspector for the current default bot, not yet a multi-policy or
  OpenEvolve runtime. The recorded interface makes that extension possible but
  does not claim it works now.
- Candidate preview shows the alternative chain and the inspector exposes its
  survivor and predicted next chain; the record also carries its predicted
  afterstate. It does not execute an alternate continuation. Weight edits rerank
  only the already-recorded candidate pool.
- `solver/bot.js` changed to expose opt-in analysis. Strict code-identity gates
  correctly treat that as identity drift even though parity tests found no move
  change. Three candidate receipts were already stale at the starting commit
  and remain stale; they were not refreshed or hidden.
- The five broad-suite failures above remain real repository state outside this
  ticket's repair scope.
